# 体系致胜GEO-信源助手 V1.4.16 · Windows / macOS 安装与 Mac 测试

本包版本为 V1.4.16，侧栏顶部提供当前任务的截图下载。可在设置选择导出目录。Windows 已有真实使用记录，Mac 安装入口和依赖已准备，等待 Mac 实机验收。

## 选择安装包

- **跨平台运行包**：新电脑使用。包含 Chrome 插件、Python 服务、Windows / macOS 安装启动脚本及本说明。先解压整个文件夹，不能只复制 extension。
- **Chrome 插件包**：仅用于已有相同版本本机服务的电脑，需解压后在 Chrome 加载。

完整功能由 Chrome 插件和本机服务配合完成。服务默认只监听 `127.0.0.1:18765`。不需要 Codex、CDP 调试、Node.js 或 Homebrew。首次安装需要联网下载 uv、Python 3.12 和依赖；FFmpeg 随对应系统的 Python 依赖提供。导入、截图和导出均不需要 API Key。

本运行包不含原电脑的任务、截图、视频、连接码、API Key 或 Python 虚拟环境。每台电脑首次启动会在解压目录的 `data/` 中建立独立资料库和连接码。Windows 与 Mac 不能共用 `.venv`，也不会自动同步历史任务。

## Mac 首次安装

1. 将跨平台运行包复制到 Mac，完整解压到长期保存的位置，例如“文稿”目录。不要在 ZIP 内运行，也不要每次重新解压到临时目录。
2. 双击 **安装依赖.command**。安装器自动识别当前机器架构，创建 Mac 的 `.venv`，然后检查依赖和 FFmpeg。支持目标为 Apple Silicon 和 Intel；应使用与机器原生架构对应的终端环境。
3. 安装完成后双击 **启动服务.command**。成功后自动用文本编辑器打开 `data/pairing-token.txt`。关闭启动窗口后服务继续运行。
4. 打开 Chrome，输入 `chrome://extensions`，启用“开发者模式”，点击“加载已解压的扩展程序”，选择解压目录中的 **extension** 文件夹。
5. 固定“体系致胜GEO-信源助手”图标，打开侧栏，在设置中粘贴本机连接码，点击“保存并连接”。底部版本应为 V1.4.16。

若双击脚本提示执行权限不足，打开 Mac“终端”，输入 `cd `（末尾有空格），把解压后的文件夹拖进终端，按回车，再依次运行：

```bash
bash ./安装依赖.command
bash ./启动服务.command
```

首次安装若找不到 uv，脚本从 `https://astral.sh/uv/install.sh` 下载官方安装器，安装到当前用户的 `~/.local/bin`，不修改 shell 配置，不要求管理员密码。官方说明：[安装 uv](https://docs.astral.sh/uv/getting-started/installation/)、[安装器选项](https://docs.astral.sh/uv/reference/installer/)。断网或下载失败会保留错误提示，可修复网络后重试，不会清理任务。

## Windows 首次安装

1. 完整解压跨平台运行包到长期保存的文件夹。
2. 双击 **安装依赖.cmd**，完成后双击 **启动服务.cmd**。缺少 uv 时从官方安装源安装到当前用户目录，然后准备 Python 3.12 和项目依赖。
3. 在 Chrome 的 `chrome://extensions` 中启用“开发者模式”，加载该目录的 **extension** 文件夹。
4. 把启动时打开的 `data\pairing-token.txt` 内容粘贴到插件设置，点击“保存并连接”。

当前正在使用且功能正常的 Windows 原目录可以继续使用，无需为了 Mac 测试重复安装插件。不要在同一台电脑同时启动两个解压目录中的服务，它们默认使用相同端口；启动器发现其他目录的服务会给出提示。

## 日常启动与停止

| 操作 | Mac | Windows |
| --- | --- | --- |
| 启动本机服务并打开连接码 | 启动服务.command | 启动服务.cmd |
| 停止服务，保留资料 | 停止服务.command | 停止服务.cmd |
| 重启服务 | 重启服务.command | 重启服务.cmd |
| 检查 Python、FFmpeg、服务状态 | 检查环境.command | 检查环境.cmd |

电脑重启后，需要重新运行“启动服务”；本版没有安装系统自启动服务。普通使用无需开着终端或 Codex，本机服务和 Chrome 需要运行。启动脚本只管理本目录的服务进程；端口或 PID 属于其他程序时拒绝停止它。

日志在 `data/service.log` 和 `data/service-error.log`；连接失败时先运行“检查环境”。不要把连接码或 API Key 作为调试截图公开发送。

## Mac 实机测试顺序

建议先用一个短问题，例如“别墅电梯推荐”，在每个平台开启联网搜索，等回答完成并展开已有信源：

1. **连接与版本**：侧栏显示“本机已连接”，“侧栏／后台／截图／清单”四项都是 1.4.16。
2. **八平台导入**：豆包、DeepSeek、文心一言、千问、元宝、Kimi、Gemini、ChatGPT 分别点击回答正文，再点击“导入信源”；核对条数、标题、链接和语义词。网站只展示部分内容时保留页面实际结果与提示。
3. **问答截图**：点击“截取提问与回答”；核对顶部有原提问、下方回答完整、无左侧历史栏。首次需要额外截图权限时按插件和 Chrome 的实际提示选择授权。截图时保持该标签页显示，不改变窗口大小；测试时也覆盖 Retina 屏幕。
4. **中文命名与导出**：用侧栏顶部的“下载截图”保存问答 PNG，再导出 Excel 和 Markdown。文件名应为“关键词-日期-平台”，截图带“问答截图”后缀。核对 Excel 的“搜索回答”页及 Markdown 的提问、回答和原图链接。PNG 与 Markdown 放在同一目录可显示图片。
5. **资料保存**：停止再启动服务，旧任务和截图仍在；任务移入回收站后可恢复。
6. **素材**：先用「提取原文」读取文章正文，再用「批量补采原文与素材」勾选本次保存视频／图集，核对视频文案和素材。

若失败，记录 Mac 系统版本、芯片类型、Chrome 版本、平台网址、按钮名称和侧栏原文。“诊断当前页面”保存到当前 Mac 的 `data/diagnostics`，Windows 不会自动收到这些文件。

## 备份与迁移

程序版本备份与任务资料分开保存。需要备份本机任务时，先停止服务，再复制整个 `data/` 文件夹到自己的备份位置；其中包含私人资料和配置。跨系统迁移历史库后，旧 Excel 中的绝对本地路径可能仍指向原电脑，不能把它视为自动跨系统同步。
